---
title: Type 1 · Overwrite
---

Type 1 slowly changing dimensions (SCDs) overwrite the existing dimension
record when an attribute changes. When a customer changes address, the old
address is replaced by the new address in the same row.

This is useful when reporting only needs the latest value and historical values
are not required.

## Dimension shape

The dimension keeps one row per customer and stores the latest descriptive
attributes:

```sql
CREATE OR REPLACE TABLE sandbox.bronze.customer (
	id BIGINT GENERATED ALWAYS AS IDENTITY,
	c_custkey BIGINT,
	c_name STRING,
	c_address STRING,
	c_phone STRING,
	c_nationkey BIGINT,
	c_mktsegment STRING,
	last_updated_at TIMESTAMP
) USING DELTA;
```

There are no effective dates or previous-value columns. The latest source
value always wins.

## Process

Type 1 is one Delta `MERGE` from `sandbox.ingress.customer` into
`sandbox.bronze.customer`. The match key is `c_custkey`. There is no separate
insert, update, or delete pass, and no history is kept.

```python
from delta import DeltaTable
from pyspark.sql.functions import col

ing_df = DeltaTable.forName(spark, "sandbox.ingress.customer").toDF()

brnz = DeltaTable.forName(spark, "sandbox.bronze.customer").alias("brz")

brnz.merge(
    ing_df.alias("ing"),
    col("brz.c_custkey") == col("ing.c_custkey"),
).whenMatchedUpdate(
    condition=(
        (col("brz.c_name") != col("ing.c_name")) |
        (col("brz.c_address") != col("ing.c_address")) |
        (col("brz.c_phone") != col("ing.c_phone")) |
        (col("brz.c_nationkey") != col("ing.c_nationkey")) |
        (col("brz.c_mktsegment") != col("ing.c_mktsegment"))
    ),
    set={
        "c_name": "ing.c_name",
        "c_address": "ing.c_address",
        "c_phone": "ing.c_phone",
        "c_nationkey": "ing.c_nationkey",
        "c_mktsegment": "ing.c_mktsegment",
    },
).whenNotMatchedInsertAll(
).whenNotMatchedBySourceDelete(
).execute()
```

The three clauses cover the Type 1 outcomes:

- **Matched and changed.** `whenMatchedUpdate` overwrites the descriptive
  columns on the existing bronze row. Unchanged matches are left alone because
  of the condition. `last_updated_at` is not in the update set, so this merge
  does not refresh it.
- **New in ingress.** `whenNotMatchedInsertAll` inserts a bronze row. `id` is
  generated by the identity column.
- **Gone from ingress.** `whenNotMatchedBySourceDelete` removes the bronze row.
  Type 1 does not keep a closed version of a deleted customer.

`c_custkey` must be unique in ingress. Delta Lake rejects a merge when more
than one source row matches the same target row.

## Type 1 versus Type 2

| Requirement | Type 1 | Type 2 |
|---|---|---|
| Rows per business key | One row | One row per version |
| History retained | No history | Complete history |
| Storage growth | Bounded by number of keys | Grows with every change |
| Best for | Current-state reporting | As-of reporting and auditability |
